3. Orange3에서 불러오기

  1. File 위젯을 캔버스에 놓고 위젯 안의 URL 탭을 엽니다.
  2. 위에서 복사한 주소를 붙여넣고 Apply(또는 Enter).
  3. 오른쪽 정보 상자에 행 수(예: 1059 instances)와 열 수가 표시되면 정상입니다. 타깃 열이 ?로 남아 있으면 4단계에서 지정합니다.

받은 파일은 캐시에 남으므로 같은 강의 중 다시 불러올 때는 즉시 열립니다.

4. 분류 워크플로

File → Select Columns(타깃 지정) → Test and Score ─┬→ Confusion Matrix ├→ Tree (규칙 시각화) ├→ Random Forest ├→ Logistic Regression └→ Predictions

① Select Columns — 타깃 지정

  • 타깃 열을 오른쪽 Target 상자로 끌어다 놓습니다(데이터셋별 타깃은 5장 참고).
  • 이름·ID·날짜 같은 식별용 열은 Meta로 보냅니다. 숫자 ID를 특징으로 두면 모델이 ID를 외웁니다.
  • 값이 하나뿐인 열(분산 없음)은 Ignore로 보냅니다.

② Test and Score — 모델 비교

  • 기본값은 Cross validation, 5 folds, Stratified이며, 이것으로 충분합니다.
  • Learners에 Tree·Random Forest·Logistic Regression을 연결하면 한 표에서 AUC·CA·F1을 나란히 비교합니다.
  • 클래스가 불균형한 데이터(②·④)에서는 AUC와 함께 F1·Precision·Recall을 보고, Target Class를 소수 클래스로 바꿔 확인합니다.

③ Confusion Matrix — 어디서 틀리는가

  • Test and Score의 결과 행을 선택한 뒤 Confusion Matrix를 열면 예측−실제 교차표가 나옵니다.
  • 부패 판정(②)에서는 Fresh를 Spoiled로 놓치는 경우(위험)와 그 반대(과잉 폐기, 비용)를 구분해 해석합니다.

④ Tree — 규칙 읽기

  • Tree 위젯에서 트리 깊이를 3~4로 줄이고, 노드를 눌러 조건과 분포를 읽습니다. "TVC가 …" 같은 규칙이 나오면 그 열이 정답을 그대로 담고 있다는 신호입니다(5장 주의 참고).
전처리 팁 — ②의 센서 ADC 값(0~65535)과 경과 시간은 단위가 크게 다릅니다. Logistic Regression·kNN을 쓸 때는 Preprocess의 Normalize를 앞에 두고, Tree·Random Forest는 정규화 없이도 됩니다. 범주형 특징(②의 Meat_Type·Packaging, ③의 0/1 지시자)을 원-핫으로 펼치려면 같은 위젯에서 Continuize를 쓰십시오.
타깃이 수치형으로 잡혔다면 — Test and Score의 Learners에 회귀 지표(MSE·RMSE)가 보이거나 Tree가 회귀 트리로 나오면 타깃이 수치형입니다. Orange3는 서로 다른 값이 3개 이상인 숫자 열을 수치형으로 읽으므로, ④의 quality처럼 원래 숫자인 타깃은 분류로 쓰기 전에 Discretize로 구간을 나눠 주십시오(①의 label은 값이 두 개라 자동으로 범주형이 됩니다).

5. 데이터셋별 요약과 주의점

① 수산물 신선도 (e-nose)

  • 타깃 label: 1 = 신선, 2 = 비신선. 원 데이터 설명에 따르면 TVC가 4.3 log cfu/g을 넘으면 비신선으로 라벨링했습니다.
  • 값이 1·2 두 개뿐이라 Orange3가 label을 자동으로 범주형 클래스로 읽습니다(별도 설정 불필요).
  • 특징: 가스 센서 8종(암모니아·CO₂·알코올·메탄·황화수소·LPG·수소)의 ppm 추정값.
  • 누출 주의: TVC는 라벨을 만든 근거 수치입니다. 특징에 넣으면 정답을 그대로 보는 셈이므로 Meta 또는 Ignore로 빼십시오. Time도 부패가 시간에 따라 진행되므로 넣으면 정확도가 거의 100%가 됩니다. "시간만으로 예측"과 "냄새만으로 예측"을 나눠 비교하면 수업 논점이 선명해집니다.
  • 클래스 불균형: 신선 21,600 대 비신선 2.8만~5.7만(어종별).
  • 어종이 다르면 가스 농도 스케일이 달라 한 파일로 합치지 않고 5개로 나눠 두었습니다. 어종별 모델을 각각 만들어 비교해 보십시오.

② 식품 부패 IoT 센서

  • 타깃 Target_Spoilage_Class: Fresh · Acceptable · Spoiled 3종. 타깃 결측 1,117행은 Orange3에서 클래스 ?로 표시되며 학습에서 자동으로 빠집니다.
  • 이 데이터는 제작자가 공개한 시뮬레이션(합성) 데이터입니다. 실측 냉장 유통 기록이 아니라, 결측·이상치·표기 불일치를 일부러 넣어 만든 교육용 챌린지 데이터입니다(제작자 설명 기준).
  • 누출 주의: Target_TVC_log10은 클래스를 만든 근거 수치입니다. 특징에서 빼십시오.
  • 그룹 누출 주의: 같은 Item_ID(10,000개 팩)를 시간에 따라 여러 번 측정한 데이터입니다. 무작위 5-fold 교차검증은 같은 팩의 다른 시점이 학습·검증에 섞여 점수를 부풀립니다. Orange3의 Test and Score에는 그룹을 지정하는 칸이 없으므로, 수업에서는 이 점을 설명하고 Test and Score의 교차검증 점수는 낙관적이라고 다루거나, Item_ID 구간으로 파일을 나눠 학습·검증을 분리하십시오.
  • 원본에 들어 있는 잡음: Beef / BEEF / "beef ", Vacuum / vac / vacuum-sealed처럼 같은 범주가 다르게 적혀 있고, 결측이 열마다 3~4%씩 있습니다. 센서 ADC가 65535(16비트 포화)로 찍힌 값이 703건 있습니다.
  • 클래스 분포(타깃이 있는 149,713행 기준): Fresh 79,675 (53.2%) · Spoiled 49,053 (32.8%) · Acceptable 20,985 (14.0%).

③ 우유 품질 등급

  • 타깃 Grade: low(429) · medium(374) · high(256) — 세 클래스가 비교적 고른 편입니다.
  • 특징 7개: pH·Temprature(°C)·Taste·Odor·Fat·Turbidity·Colour. Taste·Odor·Fat·Turbidity는 0/1 이진, Colour는 240~255.
  • 결측 없음. 원본 헤더의 Temprature는 철자 오류지만 값과 함께 그대로 두었습니다(Orange3 화면에도 이 이름으로 나옵니다).
  • 트리 하나로 규칙이 깔끔하게 나오는 데이터라 첫 실습으로 적합합니다.

④ 레드 와인 품질

  • 타깃 quality: 3~8의 6개 값(3:10 · 4:53 · 5:681 · 6:638 · 7:199 · 8:18). 순서가 있는 값이고 5·6에 82%가 몰려 있습니다.
  • Kaggle 배포본은 이미 쉼표 구분입니다(원 UCI 배포본은 세미콜론). 값은 같습니다.
  • 분류로 쓰려면 타깃 형식을 바꿔야 합니다. Orange3는 서로 다른 값이 3개 이상인 숫자 열을 수치형으로 읽으므로, quality는 그대로 두면 회귀 타깃이 됩니다. Discretize 위젯에서 quality를 골라 구간(3.5 · 4.5 · 5.5 · 6.5 · 7.5)으로 나누면 출력의 클래스가 범주형으로 바뀌어 Test and Score에서 분류 모델을 비교할 수 있습니다. 이진 분류로 묶으려면 임계값을 6.5 하나만 두어 7 이상 217건 / 그 미만 1,382건으로 나눕니다.
  • Logistic Regression을 그대로 돌리면 6개 클래스 중 소수 클래스(3·8)를 거의 못 맞힙니다. Confusion Matrix로 그 이유를 보여 주기 좋은 예제입니다.

⑤ 커피 품질 (CQI)

  • 타깃 Quality_Class(파생): A 18 · B 75 · C 86 · D 28. 근거는 원본 Total Cup Points(78.00~89.33점)입니다.
  • 누출 주의: Total Cup Points는 채점 항목(Aroma·Flavor·Aftertaste·Acidity·Body·Balance·Uniformity·Clean Cup·Sweetness·Overall)의 합계입니다. 특징에 넣으면 정답이 그대로 새므로 반드시 빼십시오.
  • 특징으로 쓸 만한 열: 위 채점 항목 10개 + Moisture Percentage·Category One Defects·Category Two Defects·Quakers.
  • Meta/Ignore로 보낼 열: ID·Farm Name·Lot Number·Mill·ICO Number·Company·Producer·Region·Grading Date·Expiration·Owner·Certification Body/Address/Contact·Altitude·Bag Weight. 이름·주소·날짜는 값 종류가 너무 많아 분류에 도움이 안 되고 과적합만 만듭니다.
  • 값이 하나뿐이라 정보가 없는 열: Status(전부 Completed), Clean Cup·Sweetness(전부 10.0), Defects(전부 0).
  • 207행뿐인 소형 데이터입니다. 정확도 한 숫자보다 교차검증 점수의 흔들림(표준편차)을 함께 읽는 연습에 적합합니다.
